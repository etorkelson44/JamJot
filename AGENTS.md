# JamJot development
Read docs/HANDOFF.md before starting. Check the current branch, latest commit, open pull request and uncommitted work. Ask the owner for the current private product requirements if needed. Review implementation evidence before changing behavior. Resolve conflicts with the owner before changing approved scope.

Make changes on an agreed task branch. Use fictional data in tests. Keep credentials, real lesson sheets, recordings, account details, private planning and chat links out of commits and test fixtures. Review workflow triggers before pushing. Production schema changes, deployments and merges to main require separate approval.

Record small checkpoints as work progresses. At handoff, update docs/HANDOFF.md with the branch, last code commit, changed behavior, tests and results, migration or deployment status, unresolved issues and next step. Push the authorized task branch so the next assistant can retrieve it. Keep one active writer per task branch.
